## The problem

In a practice team project, keeping track of unfinished tasks meant checking the same list every week. I wanted a reminder that helped the team see what needed attention without sending unnecessary messages.

## Starting with a small workflow

Before choosing a tool, I wrote down three things: when the reminder should run, which tasks counted as unfinished, and who needed to receive it. This made the scope easier to explain.

1. Keep tasks in one shared list.
2. Check each task status on the agreed day.
3. Send one summary of the tasks that still need attention.

## Testing before sharing

I would test a completed task, an unfinished task and an empty list. I would also check what happens when a task has no owner, so the reminder does not fail silently.

## What I learned

The useful part of automation is understanding the problem first. A small workflow is easier to test, explain and improve. In a team, agreeing on the task names and ownership matters just as much as choosing the tool.

## My next step

I would ask a teammate to try the workflow and explain what was unclear. That feedback would guide the next change.
